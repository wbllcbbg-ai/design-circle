# 装修设计平台 · 完整产品方案（信任优先版）

> 本版在「终版」基础上做了一次战略转向与若干硬伤补全。
> **根本差异一句话**：装修是高信任决策，业主不会把钱托给一个还没建立信任的新平台——所以**信任先建、资金托管后置**；但放弃托管不等于放弃交易，平台用**「过程托管」**（不碰钱、但掌握交易过程）来同时解决变现、防跳单、信用积累三件事。

---

## 序：为什么是「信任优先」而非「交易优先」

原终版方案的战略框架（分阶段验证、不预设堆功能、法律边界清晰）是扎实的。但它把**资金托管**当成了一个技术接入任务，低估了两件事：

1. **合规红线**：设计费（2–5万）尤其未来施工款（几十万）沉淀在平台，涉及支付牌照/二类账户/资金存管资质。无资质搞资金池、动用托管资金孳息，是明确的合规雷区。
2. **信任门槛**：消费者心理上，一个新平台 + 一笔几万的托管，转化率会非常低。在信任未建立前强推托管，会同时压垮转化和口碑。

**但放弃托管会引爆两个新问题**：① 核心盈利（佣金+沉淀收益）失去抓手；② 失去最强防跳单武器（钱在平台=跳不了）。

本版的解法是：**放弃「资金托管」（碰钱），但不放弃「交易托管」（掌握过程）。** 过程托管用电子合同 + 交付节点确认 + 发票流，让平台在不碰一分钱的前提下，掌握交易的真实性——据此收合同服务费、据此防跳单、据此沉淀只属于平台的真实信用。这是本版的核心创新，也是整套飞轮的引擎。

## 一、产品定位

一个以**真实装修口碑内容**为核心信任资产、连接业主与设计师/材料商/施工方/监理的平台。

- **现阶段（信任建设期）**：装修行业的大众点评 + 小红书——靠真实内容聚拢业主，商家为曝光/线索/真实交易凭证付费。
- **远期（信任成熟后）**：交易服务商——在信任充分时，可选地引入资金托管，完成从「信息撮合」到「资金撮合」的升级。

两条核心线（沿用终版，成立）：
- **内容线**：逛案例、读文章、看日记、搜风格、刷问答——用户被真实内容留住。
- **服务线**：找设计师→咨询→（过程托管）签约→交付确认→评价——用户带着问题来，解决问题走。

交汇点是**设计师主页**——内容线的终点，服务线的起点。

## 二、核心商业模式：信任飞轮 + 过程托管

### 2.1 信任飞轮（核心引擎）

```
真实内容/案例/评价（只来自平台见证的真实交付）
        │  越真实，越可信
        ▼
   业主信任平台
        │  口碑传播、自然增长
        ▼
   业主规模（流量）扩大
        │  设计师/材料商离不开这个流量
        ▼
   商家为曝光/线索/交易凭证付费
        │  平台有收入
        ▼
   激励更多真实内容（业主日记、真实评价）
        └──────── 飞轮加速 ─────────┘
```

**飞轮的根基是「真实」**——而真实信用的唯一来源，是平台见证过的真实交付（见 2.2）。这一点必须写进产品的 DNA：AI 内容可以用来冷启动填充，但**永远不会被计入信用分**，也永远不会获得「平台验证」标签。

### 2.2 过程托管：不碰钱，但掌握交易

这是本版替代「资金托管」的核心机制。

**平台不碰一分钱**（业主和设计师自行结算），但平台掌握交易过程的四个锚点：

| 锚点 | 平台掌握什么 | 作用 |
|------|------------|------|
| **标准化电子合同**（法大大等） | 合同条款、付款节点、**平台服务费条款** | 平台服务费是合同义务，不依赖资金流抽成 |
| **交付节点确认** | 设计师提交方案/施工图→业主在平台确认 | 只有平台确认的节点才算「真实交付」 |
| **发票/收据流** | 设计师向平台报税开票，资金流可追溯 | 交易真实性证据 |
| **评价绑定交付** | 只有平台见证的项目才能产生评价/完工数 | 信用数据的真实性闸门 |

**这套机制一举三得**：

1. **变现**：平台按合同向设计师收「平台服务费/信息服务费」（非资金抽成），合规上不需要支付牌照。
2. **防跳单**：设计师跳单可以，但他跳了就没有平台交付确认、没有真实评价、没有信用积累——而平台靠信用筛选设计师，跳单者信用永远是 0，被自然淘汰。
3. **真实信用**：信用只来自平台见证的交付，AI 内容无法造假——这就是无法被复制的护城河。

> 一句话：**业主可以跳「钱」，但跳不了「过程」和「交付物」。平台握住后者，就握住了飞轮。**

### 2.3 前期盈利模型（资金托管后置后）

| 收入来源 | 是否成立（无资金托管） | 定位 |
|---------|:---:|------|
| **合同服务费（设计师）** | ✅ | 核心——基于过程托管的平台服务费 |
| **材料商线索费/广告** | ✅ | 核心——流量生意，最现实 |
| **设计师增值服务**（置顶/曝光/优先匹配） | ✅ | 增量——需足够业主流量 |
| 案例内容合作（材料商植入，标注软广） | ✅ | 增量 |
| 资金托管佣金 + 沉淀收益 | ⏸️ | **后置**——信任成熟后才上 |

> ⚠️ **放弃「设计师提点=资金流抽成」的思路**。无托管下平台感知不到私下交易，按资金流抽成不可执行。必须改为「合同服务费」（见 2.2）。

### 2.4 单位经济（必须先算清的一笔账）

单笔设计费交易的 P&L（示例，需用真实数据校准）：

```
单笔毛收入（合同服务费，假设设计费3万×服务费率8%）= 2,400元
减：
  - 获客成本（分摊）         ?  ← 必须测出
  - 人肉/运营接单成本         分摊
  - 法大大签约费              按次
  - 支付通道费（业主侧）      按笔
  - 新人模式补贴（如适用）    设计费补贴30%封顶
  = 单笔净收入
```

**盈亏平衡反推**：月成交多少设计单才打平运营成本？这个数没算出来，就不能说「阶段二跑通第一笔交易」之后能规模化。**阶段二启动前必须先有这张表。**

## 三、防跳单体系（结构性留人，而非对抗性惩罚）

冷启动期「信用资产」没有数据支撑，对设计师无约束力。放弃资金托管后，平台不能靠「钱锁人」，但可以用「**不跳单才有未来**」留人：

| 机制 | 原理 |
|------|------|
| **信用筛选即防跳单** | 平台只把业主流量导给有平台交付记录的设计师；跳单者无记录、无评价，自然拿不到单。 |
| **正向激励为主** | 完成平台见证的交付 → 信用加分 → 更多曝光 → 更多单。跳单=放弃这条上升通道。 |
| **惩罚为辅、且可执行** | 跳单被确认（业主举报/同行举报/平台抽查）→ 降级/曝光。但承认冷启动期「发现跳单」很难，惩罚不是主武器。 |
| **过程托管的自然约束** | 设计师想被推荐、想拿真实评价，就得让交易「过」平台。这是诱导而非封堵。 |

> 关键认知：**防跳单靠的不是检测每一笔私下交易，而是让「走平台」比「跳单」更有利可图。** 这依赖两件事——① 信用体系真实有效；② 平台流量足够大（设计师离不开）。两者都在本版的飞轮里。

## 四、AI 内容的定位（冷启动工具 + 长期补充，动态调整）

用户决策：**AI 内容既不全盘否定，也不作为长期主力——动态调整**。

### 4.1 角色定位

| 阶段 | AI 内容的角色 | 真实内容的角色 |
|------|--------------|---------------|
| 冷启动期 | 主力填充（案例/文章/攻略） | 几乎没有，靠激励逐步引入 |
| 信任建设期 | 逐步**退化为补充**（攻略类、知识类） | 成为主力（真实案例/日记/评价） |
| 成熟期 | 仅作知识内容辅助 | 绝对主力，信用数据只来自真实交付 |

### 4.2 三条铁律（防止 AI 内容反噬信任）

1. **AI 内容永不计入信用**：`virtual_user_id` 标记的内容，不产生完工数、好评率、信用分。
2. **AI 内容永不获得「平台验证」标签**：来源标注体系（见第九章）下，AI 内容只能标「AI 生成」或「示范」，绝不能冒充真实。
3. **明确的退出/过渡话术**：阶段二真设计师入驻时，向早期用户交代「部分案例为示意/示范内容」，避免信任崩塌。

### 4.3 与现有代码的关系

现有 AI 内容工厂（策略引擎/虚拟人/生态平衡/指纹散射）是**冷启动期的真资产**，但：
- 它产出的「假繁荣」（模拟点赞/评论/评价）必须与真实互动**数据隔离**，不能污染信用。
- 运营策略引擎维持现状即可，**不要再加功能**——它的边际价值已经很低，资源应转向真实内容获取和过程托管。

## 五、获客策略（原方案缺失，本版新增）

**这是阶段一能否启动的前置条件，不是「以后再说」。** 阶段一的漏斗验证完全依赖流量，没有流量就没有有效样本。

### 5.1 低成本渠道优先（重庆本地）

| 渠道 | 玩法 | 预期 CAC | 备注 |
|------|------|---------|------|
| 抖音同城/小红书本地 | 真实装修干货/避坑短视频，导流 | 低 | 内容即获客，与平台内容线协同 |
| 本地装修群/业主群 | 真实案例/避坑分享 | 极低 | 但易被视为广告，需真实身份 |
| 物业/小区合作 | 新交付小区集中地推 | 中 | 精准，转化高 |
| 投流（巨量/腾讯） | 精准投放 | 高 | 仅在验证转化后放量 |

### 5.2 验证样本量

阶段一每个阶段需定义「最小有效样本量」和「验证周期」。否则「数据驱动」会变成「想等多久等多久」。建议：日均 UV、咨询发起数、**深度咨询数**（见 6.2）三指标，连续 2 周达标才进阶段二。

## 六、阶段化路线图（修正版）

> 核心逻辑不变：按数据反馈决定，不预设堆功能。但每个阶段的**验证指标要更强**（见 6.2），且**盈利路径要提前明确**。

### 阶段一：真实内容 + 入口验证（≈几周）

**核心假设**：用户愿意在平台上找设计师。

| 功能 | 说明 |
|------|------|
| AI 内容流（冷启动） | AI 生成案例铺首页，但内容来源标注「AI/示范」 |
| 设计师主页 | AI 虚拟设计师简介 + 作品集 + 咨询按钮 |
| 案例→设计师链路 | 内容卡片设计师头像可点进主页 |
| 对话系统（最简版） | 用户咨询 → 运营人肉接单回复 |
| **真实内容引入激励** | 邀请少量真实业主写日记/晒家（补贴） |
| **转化漏斗统计** | 浏览→进主页→咨询→**深度咨询**（四段） |

**验证标准（强化）**：不止「有咨询量」，更要追到**「深度咨询率」**（咨询中产生了具体需求：面积/预算/风格，且用户未立即消失）——这比「发起咨询」更接近付费意愿信号。

**诚实说明**：AI 精美案例下的咨询，可能是「图好看随便问问」，不等于「愿意花3万设计费」。验证指标必须更靠近付费意愿。

### 阶段二：真设计师入驻 + 过程托管（≈2–3个月）

**前提**：阶段一验证通过（有足够深度咨询量）。

**核心假设**：用户愿意通过平台与设计师签约（但**钱私下结算**，平台只托管过程）。

| 功能 | 说明 |
|------|------|
| 设计师入驻（最简版） | 真实资质审核（见第七章），数据标注「自述/核实/验证」 |
| **过程托管** | 电子合同 + 交付节点确认 + 评价绑定（不碰资金） |
| 结构化报价模板 | 标准化字段嵌入对话 |
| 简化项目页 | 线性里程碑（量房→方案→施工图→尾款节点）+ **交付看板** + 对话 |
| 信用数据（初版） | 完工数 + 好评率 + 来源标注，**只来自平台见证交付** |
| **合同服务费** | 平台按合同收服务费（核心变现） |

**验证标准**：跑通第一笔真实设计师签约 + 交付确认 + 真实评价，且平台收到合同服务费。

**不需要的**：资金托管、施工方、监理到场、变更管理、预算管控、纠纷裁量。

### 阶段三：数据驱动扩展（不预设）

根据阶段二数据决定，工具箱而非路线图：

| 如果数据显示 | 则引入 |
|-------------|--------|
| 信任已充分、用户要求托管 | **资金托管**（信任成熟后，可选升级） |
| 纠纷集中在施工 | 施工方 + 监理到场 |
| 预算超支高频 | 预算预警 + 变更管理 |
| 设计师需要更多曝光 | 增值服务（搜索排名、推荐位） |
| 多城市有需求 | 城市合伙人后台 |
| 没人用 | 回到阶段一 |

## 七、设计师准入与资质校验（沿用终版，成立）

三级校验 + 主页数据来源标注：

| 级别 | 校验内容 | 通过后 |
|------|---------|--------|
| L1 实名 | 身份证 OCR + 人脸活体 | 主页「已实名」 |
| L2 资质 | 资格证/职称证/营业执照 + 人工核验 | 主页「资质已核实」 |
| L3 背景 | 作品真实性抽查 + 无重大纠纷 | 主页「背景已核实」 |

**数据来源标注（关键原则）**：
- 🟢「平台验证」：来自平台见证交付的数据（完工数/好评率/工期）
- 🟡「平台已核实」：L1+L2 通过的身份/资质
- ⚪「设计师自述」：设计师自己填的（从业年限、自报项目数）
- 三者必须在视觉上区分，让业主一眼分辨。

## 八、对话系统状态机（沿用，需在阶段二补）

```
[新对话] → 咨询中
            ├── 设计师已报价 → 业主确认 → [生成合同]
            │                          └── 业主拒绝 → 对话归档
            ├── 设计师拒绝 → 对话归档（不影响信用）
            └── 超时24h未响应 → 对话归档（影响响应率信用分）
合同签署后 → 对话自动绑定项目 → 不可删除
项目竣工后 → 对话只读保留（证据链）
```

> 当前代码 conversations 无状态字段，需在阶段二补。

## 九、信用体系（强化真实性）

### 9.1 多维信用（设计师）

| 指标 | 来源 | 影响 |
|------|------|------|
| 完工项目数 | 平台见证交付 | 排序权重 |
| 结构化评价均分 | 平台见证项目 | 主页展示 |
| 项目逾期率 | 平台见证 | 接单资格 |
| 咨询响应速度 | 平台数据 | 匹配推荐 |
| 纠纷记录 | 平台记录 | 主页警示 |
| **跳单记录** | 平台确认 | 降级/曝光 |

**铁律：以上所有指标只来自平台见证的真实交付。** AI 虚拟人的内容一律不计入。

### 9.2 评价维度

| 方向 | 维度 |
|------|------|
| 业主→设计师 | 设计质量、沟通效率、施工跟进、预算控制、工期控制 |
| 设计师→业主 | 配合度、付款及时性、决策效率 |

### 9.3 关键原则

信用数据**必须暴露缺陷**：95% 好评但有一条差评且认真回复了的设计师 > 100% 好评但项目太少的设计师。差评 + 回复比完美评分更可信。

## 十、内容审核体系（沿用终版三层管线，分阶段落地）

```
第一层：机审（全覆盖）—— 文字敏感词 + 图片AI审核 + 外链检测 + 重复检测
第二层：人审队列（机审命中）—— 低风险放行/中风险2h内/高风险拦截
第三层：事后巡检 —— 已发布抽查5% + 举报触发 + 高频用户专项
```

| 阶段 | 方案 |
|------|------|
| P0–P1 | 全人工（量不大），架构预留 |
| P2–P3 | 接第三方（阿里绿网/腾讯天御）+ 自建人审队列 |
| P4 | 完善机审模型 + 人审效率工具 |

> 当前代码的「AI 审核点评」只是粗糙关键词过滤，**比方案弱**，需按阶段升级。

## 十一、角色体系（五角色，分阶段引入）

| 角色 | 引入阶段 | 说明 |
|------|---------|------|
| 业主 | 阶段一 | 核心 |
| 设计师 | 阶段一（虚拟）/ 阶段二（真实） | 核心 |
| 材料商 | 阶段二~三 | 线索费变现的关键 |
| 施工方 | 阶段三（数据驱动） | 默认设计师自带，平台不介入施工 |
| 监理 | 阶段三（数据驱动） | 独立入驻 + 信用 + 师徒制 |

**阶段二只做设计费相关**：砍掉施工方、监理到场、变更管理、预算管控、纠纷裁量（与终版一致）。

## 十三、法律责任边界（沿用终版，强化）

平台定位：**交易服务提供商**，不是装修总包。

| 场景 | 平台做 | 平台不做 |
|------|--------|---------|
| 设计缺陷 | 协调 + 按合同退款 | 不承担连带赔偿 |
| 施工质量 | 协调 + 监理发现问题 | 不承担连带责任 |
| 材料质量 | 协调 + 材料商保证金 | 不承担连带责任 |
| 设计师无法履约 | 匹配替代 + 结算已完成 | 不确定工期损失 |

**资金不沉淀**：阶段二过程托管下，平台不碰资金、不动孳息，与「交易服务商非总包」定位一致。

## 十四、供给侧调研（原方案缺失，本版新增）

阶段二启动前，必须做一次真实供给侧访谈，避免开发完才发现设计师不接招：

- 找 5–10 个重庆本地设计师聊：「如果有平台帮你接单、设计费由你在平台外自行收取、平台按合同收服务费、交付节点在平台确认，你接不接受？」
- 如果设计师普遍拒绝「平台外自行收款 + 平台收服务费」模型，需调整服务费率或交付物托管方式。
- 监理供给：本地专业家装监理稀缺，派单模式供给可能跟不上，阶段三引入前先摸供给。

## 十六、关键产品原则（本版修订）

1. **信任是根基，资金托管是果不是因**——先建信任，托管后置。
2. **放弃资金托管，但不放弃交易托管**——过程托管是变现+防跳单+信用的统一引擎。
3. **防跳单靠正向激励，不靠对抗惩罚**——走平台比跳单更有利可图。
4. **信用只来自平台见证的真实交付**——AI 内容永不计入信用，这是无法复制的护城河。
5. **所有数据标注来源**（🟢平台验证 / 🟡已核实 / ⚪自述 / AI 示范）——让业主一眼分辨。
6. **信用数据必须暴露缺陷**——差评+回复 > 完美评分。
7. **对话和项目不分离**——沟通沉淀在项目页，纠纷有据可查。
8. **做「交易服务商」不做「装修总包」**——法律责任边界清晰，资金不沉淀。
9. **分阶段验证，数据决定下一步**——但每阶段定义最小样本量和验证周期。
10. **验证指标要靠近付费意愿**——不止「咨询」，追到「深度咨询」。
11. **单位经济先算清**——单笔 P&L + 盈亏平衡单量，是生意成立的命门。
12. **获客是阶段一前置条件**——不是「以后再说」。
13. **供给侧先调研**——别等开发完才发现设计师不接招。
14. **AI 内容是冷启动工具，不是长期主力**——动态退化为补充。
15. **MVP 项目页是信息透明工具，不是管控工具**——线性里程碑 + 交付看板 + 对话。
16. **城市维度从 Day1 数据隔离**——后期拆分成本巨大。
17. **砍掉阶段二不必要的**——施工方、监理、变更、预算管控、纠纷裁量全部后置。
